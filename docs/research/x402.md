# x402 notes (verified 2026-11-05 against x402-foundation/x402 @ 6a773dba, npm 2.30.0)

Canonical repo: github.com/x402-foundation/x402 (coinbase/x402 is a fork). Packages `@x402/{core,evm,hedera,hono,fetch,extensions}` all 2.30.0; core depends on zod ^4.

## Transport v2 (specs/transports-v2/http.md)
| | Header | Content |
|---|---|---|
| 402 response | `PAYMENT-REQUIRED` | base64(JSON PaymentRequired) |
| client retry | `PAYMENT-SIGNATURE` | base64(JSON PaymentPayload) |
| success | `PAYMENT-RESPONSE` | base64(JSON SettleResponse) |
- Standard base64 (not url). Helpers in `@x402/core/http`. 402 body not used for protocol data (`{}` or `{error}`), add `Cache-Control: no-store`.
- Failed verify → 402 again with fresh PAYMENT-REQUIRED whose `error` = invalidReason. Failed settle → 402 + PAYMENT-RESPONSE success:false.
- CORS for browsers: allow headers `PAYMENT-SIGNATURE, Content-Type, Access-Control-Expose-Headers`; expose `PAYMENT-REQUIRED, PAYMENT-RESPONSE`.

## Shapes
```ts
PaymentRequirements = { scheme; network /*CAIP-2, /^[-a-z0-9]{3,8}:[-_a-zA-Z0-9]{1,32}$/*/; asset; amount /*atomic string*/; payTo; maxTimeoutSeconds; extra /*always send, {} ok*/ }
PaymentRequired = { x402Version: 2; error?; resource: { url; description?; mimeType?; serviceName?; tags?; iconUrl? }; accepts: PaymentRequirements[]; extensions? }
PaymentPayload = { x402Version: 2; resource?; accepted: PaymentRequirements; payload: Record<string,unknown>; extensions? }
VerifyResponse = { isValid; invalidReason?; invalidMessage?; payer?; extensions?; extra? }
SettleResponse = { success; errorReason?; errorMessage?; payer?; transaction /*"" if none*/; network; amount?; extensions?; extra? }
```
Reserved `extra` keys: `assetTransferMethod`, `paymentFlow` ("authorization" default | "upfront" | "escrow"; clients drop unknown flows).

## Facilitator HTTP
- `POST /verify`, `POST /settle` body `{ x402Version: 2, paymentPayload, paymentRequirements }` → always HTTP 200 with isValid/success flags (non-2xx makes client throw).
- `GET /supported` → `{ kinds: [{ x402Version: 2, scheme, network, extra? }], extensions: [], signers: { "eip155:*": ["0x.."] } }`.
- Optional discovery: `GET /discovery/resources?type&payTo&scheme&network&limit&offset` → `{ x402Version: 2, items: [{ resource, type: "http", x402Version, accepts, lastUpdated, description?, ... }], pagination: { limit, offset, total } }`.

## @x402/core extension points (`@x402/core/types`)
- Client: `SchemeNetworkClient { scheme; findDefaultAsset?(asset, network); createPaymentPayload(x402Version, req, ctx?) → { x402Version, payload } }`, `new x402Client().register(network, impl)`.
  - GOTCHA: default spend controls reject assets unknown to `findDefaultAsset` and cap at "$1"/payment → implement `findDefaultAsset` or `setSpendControls({allowedAssets:[...]})`.
- Server: `SchemeNetworkServer { scheme; defaultAssetTransferMethod: "default"; paymentFlows: { default: { supported:["authorization"], default:"authorization" } }; schemeHooks?; dynamicExtraFields?; parsePrice(price, network) → {amount, asset, extra?}; enhancePaymentRequirements(req, supportedKind, facilitatorExtensions) }`, `new x402ResourceServer(facilitatorClient).register(network, impl)`.
  - Server only builds requirements if facilitator `/supported` lists the exact scheme+network at startup (else RouteConfigurationError → process.exit(1) in Hono adapter). Start facilitator first; register concrete networks, not wildcards.
  - Server matches `payload.accepted` deep-equal on core fields; server `extra` must be a subset of client `extra`.
- Facilitator: `SchemeNetworkFacilitator { scheme; caipFamily: "eip155:*"; getExtra(network); getSigners(network); verify(payload, req, ctx?); settle(payload, req, ctx?) }`, `new x402Facilitator().register([networks], impl)`. No Hono facilitator package — hand-roll the 3 routes.
- `@x402/hono`: `paymentMiddleware(routes, resourceServer, paywallConfig?, paywall?, syncFacilitatorOnStart=true)`; routes `{ "GET /path": { accepts: { scheme, price, network, payTo, maxTimeoutSeconds?, extra? }, description?, mimeType?, extensions? } }`.
- `@x402/fetch`: `wrapFetchWithPayment(fetch, client)` — always 402 round trip, no preemptive pay.

## batch-settlement (official, for reference — ours is `leash-batch`)
- Voucher `Voucher(bytes32 channelId,uint128 maxClaimableAmount)`, cumulative, no nonce/expiry; next = charged + amount.
- Self-managed mode: server verifies vouchers locally; PAYMENT-RESPONSE has `transaction: ""`, `extra: { chargedAmount, channelState }`. Deposits go through facilitator /settle (facilitator pays gas). Channel manager periodically claims/settles/refunds.
- Contract `x402BatchSettlement` at 0x4020074e9dF2ce1deE5A9C1b5c3f541D02a10003 (Base, Base Sepolia, Arb Sepolia, Eth Sepolia, **Hedera testnet 296**). Needs EIP-3009/Permit2 deposits.
- Differences we lean on: our mandate is onchain (caps/allowlist/expiry), the payer never needs EIP-3009, and root authority is post-quantum.

## Discovery
- Official: Bazaar extension (`extensions.bazaar = { info: { input: {type:"http", method,...}, output? }, schema }` in the 402) + facilitator `/discovery/resources`.
- `/.well-known/x402` only in IETF draft-hawkins-x402-dns-discovery-03 (non-normative): `{ x402Version, kind: "resource-server", name, description, resources: [{ url, method, description }], facilitator?: { baseUrl, endpoints: {supported, verify, settle}, kinds, assets }, updated }`.
- Plan: merchant serves `/.well-known/x402` (draft format) and bazaar info in 402s; facilitator serves `/discovery/resources`.

## Hedera `exact` (fallback path for the Hedera prize)
- Networks `hedera:testnet` / `hedera:mainnet`. Asset `0.0.0` = HBAR (tinybars) or HTS token id. Testnet USDC = **0.0.429274** (6 dp). `payTo` = `0.0.x`.
- `extra.feePayer` required (from facilitator `/supported`). Payload `{ transaction: base64(partially signed TransferTransaction) }`; facilitator co-signs as fee payer and submits.
- Facilitator: `toFacilitatorHederaSigner({ getAddresses, signAndSubmitTransaction: createHederaSignAndSubmitTransaction(...), verifyPayerSignature: createHederaVerifyPayerSignature(), preflightTransfer: createHederaPreflightTransfer() })`, `facilitator.register("hedera:testnet", new ExactHederaScheme(signer))`. Imports `@x402/hedera/exact/{client,server,facilitator}`.
- Settle returns `transaction: "0.0.<feePayer>@<secs>.<nanos>"`. Payer + payTo must be associated with the token.
